## What shipped

Assignment and returns end to end: a partial unique index giving each asset at most one open assignment, a tx-scoped transition core that assign/return/repair/retire all share, an append-only `ASSIGNED`/`RETURNED` event pair linked by FK rather than by name, `/people/[id]` and a self-scoped `/me/assignments`, and a role-tiered PII model in which `STAFF_RO` causes no person data to be **fetched** anywhere outside their own assignments.

## What surprised us

1. **The story was mis-tiered in the PRD, and the reason was invisible until the ACs were read together.** AC-3 ("per-asset history, every holder") and AC-4 ("nobody else's details beyond name") are individually unremarkable; read together they decide whether every read-only staff member gets a browsable custody map of the organisation's kit. That is a PII/authorisation decision, which floors at T3 — so the T2 estimate was not a scheduling error, it was a missing reading of the ACs. **Tier estimates made at intake need re-deriving when the ACs are read in detail, not inherited.**

2. **Three separate accounts of one guard were wrong, in sequence.** A comment claimed the `returnedAt IS NULL` + `count === 1` predicate "survives someone deleting the lock". The advisor proved it does not (the losing transaction finds the row already closed and exits early). Its correction — "defends a narrow interleaving inside the lock's window" — was also wrong, because the reviewer then proved the assertion was _unfalsifiable_: deleting the throw left all 213 tests green. The truth turned out to be that the lock is on the **Asset** row while the contended row is an **Assignment**, so a direct `Assignment` writer is not excluded by it at all — a window the lock structurally cannot cover, and the one the predicate actually defends. Only the third account has a test behind it.

3. **A guard added late silently invalidated an earlier guard's red-proof.** Copilot's finding produced a new "repair-bound returns need a note" rule, which broke the designated lock-proof test — whose repair transition lands on an `ASSIGNED` asset by construction. Fixing the test was right, but it meant the headline concurrency proof had to be re-run to stay true.

4. **`P2002` quietly stopped meaning one thing.** With a second unique index, "not the tag index ⇒ assignment conflict" produces confidently wrong sentences. Probing the real error shapes showed `Person.email` collides as `target: ["email"]` — so a duplicate person would have told an operator "that asset is already assigned to someone", one `Person` write away.

5. **The reviewer's blocking finding arrived against a stale snapshot.** Two of its three blockers were already fixed by a commit that landed while it worked. Not wasted — it re-verified them — but a parallel gate reviewing a moving branch will re-report closed findings.

6. **A subagent hit its session limit mid-task.** Its work was uncommitted but complete enough to finish by hand, including a leak fix it had applied after being flagged. Delegation survived the failure because the task had a written spec and file ownership; a vaguer handoff would have been unrecoverable.

7. **A migration checksum drift blocked all local DB work and was invisible in CI.** AM-02's migration was hand-edited after being applied locally, so `migrate dev` refused to run. Prisma's remedy (`migrate reset`) destroys data and is gated behind a consent prompt. The DBs were structurally correct — only the bookkeeping was stale.

## What we'd do differently

- **Re-derive the tier from the ACs at the start of `/ship`, treating the PRD's tier as an estimate.** AM-03's real tier was legible in ten minutes of reading.
- **Give every guard its own red-proof against its own window**, and re-run the affected proofs whenever a later guard changes the paths they exercise.
- **Write comments that claim only what a test demonstrates.** Every false safety claim here was plausible and confidently worded; the fix was never the code, always the sentence.
- **Snapshot the review commit.** Tell parallel gates the SHA they are reviewing, so a fix landing mid-review is distinguishable from an unaddressed finding.

## Carry-forwards (into AM-04's plan, before implementation)

- **AM-04-CF-A (partly resolved).** `createOpenAssignmentTx` now takes the asset lock itself. Binding on AM-04: a bulk import calling it in a loop takes one row lock per asset, so it **must iterate sorted by `assetId`** — two concurrent imports over overlapping sets in opposite orders deadlock, and re-running a seemingly-stuck import is exactly what a nervous operator does.
- **AM-04-CF-B.** Bring AM-04's write paths inside the scoped reconciliation assertion, or it narrows silently as the codebase grows.
- **AM-04-CF-C.** The import inserts an open `Assignment` directly with `checkedOutAt` from source data plus the reserved `IMPORTED` event. It must **not** call `assignAsset` — that would fabricate an `ASSIGNED` event dated today for a handover from two years ago.
- **AM-05.** The finance export consumes the `personSelectFor` tiers; a CSV carrying `Person.email` would contradict the tier table now recorded in `docs/DPA-TRANSFER-NOTE.md` — a written compliance claim, not a style preference.
- **AM-07.** `STAFF_RO` must not search by person name. **Sharper:** if AM-07 indexes `AssetEvent.notes`, every operator-typed name in that append-only column becomes findable by `STAFF_RO` — a worse bypass than name search, because it cannot be corrected.
- **AM-03-CF-1 / CF-2** stand: no Person admin; leaver open assignments deliberately unenforced.
- **AM-03-CF-3.** A one-step reassign would make `eventTypeFor` reachable with both an opened and a closed assignment; it now throws rather than dropping a custody period.

## Accepted residual risk

`AssetEvent.notes` is operator-typed free text rendered to all four roles including `STAFF_RO`, in a table never updated or deleted. The code never writes PII there; an operator can. Mitigated by a hint on every form that writes it and a `CLAUDE.md` entry — guidance, not enforcement. It is the one channel through which the `STAFF_RO` redaction can be bypassed.
